# @headless-three/renderer Compatibility Matrix

This matrix is the public support contract for the current renderer. The package accepts normal Three.js scene objects and renders through the TypeScript adapter, N-API, and native `wgpu`; it does not provide a WebGL context or emulate `THREE.WebGLRenderer`.

Status keys:

- **Supported**: implemented and covered by smoke or conformance tests.
- **Partial**: implemented for common cases, with known gaps listed here.
- **Unsupported**: not implemented; scenes should be preprocessed or should expect clear documented gaps.

## Public API

| Feature | Status | Notes |
|---|---|---|
| `render(scene, camera, options)` | Supported | Accepts a `THREE.Scene` or `THREE.Object3D` root and returns PNG by default or raw RGBA when `options.format` is `'rgba'`; malformed scene/children/camera/userData/option containers, unsupported output formats, invalid explicit or aspect-derived dimensions, and invalid camera clipping ranges or matrix containers/values fail clearly. |
| `Renderer` reusable instance | Supported | Reuses the native renderer object across calls. |
| `renderToTarget()` / `options.target` | Supported | Populates non-array target-like `{ width, height, data, texture.image.data, texture.source.data }` fields for a single color output, including one-element `target.texture` arrays, `target.textures[0]`, and single-attachment MRT-shaped targets. Top-level `target.data` remains RGBA8; color textures receive Alpha/Red/RG/RGB/RGBA byte data by requested format, normalized `Float32Array` data for `THREE.FloatType`, signed or unsigned normalized integer arrays for `ByteType`/`ShortType`/`IntType` and `UnsignedShortType`/`UnsignedIntType`, packed `Uint16Array` data for `UnsignedShort4444Type`/`UnsignedShort5551Type`, packed `Uint32Array` RGB9_E5 data for `UnsignedInt5999Type`, or `Uint16Array` half-float data for `HalfFloatType`. Target `depthTexture` objects receive normalized depth readback with image/source writeback, including scissor clipping, base-texture and alpha-map alpha-tested cutouts, and transparent material default/explicit `depthWrite` behavior; `THREE.FloatType` depth textures receive scalar `Float32Array` data, `HalfFloatType` receives `Uint16Array` half-float data, `UnsignedByteType`/`UnsignedShortType`/`UnsignedIntType` depth textures receive scalar unsigned typed arrays, `UnsignedInt248Type` receives `Uint32Array` data with normalized depth24 in the high bits and zero stencil bytes, and plain depth target objects receive RGBA8 bytes. 4x MSAA resolves into target readback buffers; malformed targets, target image containers, nested target texture/mipmap/source containers, malformed target scissor flags, multiple color attachments, array/3D target texture objects, regular-camera cube target texture objects, unsupported sample counts, unsupported color target texture format/type requests, and unsupported depth texture type/format pairings fail clearly. |
| Post-processing options | Supported | Exposure, contrast, saturation, vignette, grayscale, and invert; invalid effect values fail clearly. |
| WebGLRenderer-compatible state machine | Unsupported | Non-goal. The contract is scene input and image/target output. |

| MSAA controls | Partial | Render-option and target sample counts support 4x MSAA with resolve into normal output and target readback buffers. `material.alphaToCoverage` uses native alpha-to-coverage for multisampled renders, with generated browser-reference corpus coverage for the current 4x-MSAA path.
